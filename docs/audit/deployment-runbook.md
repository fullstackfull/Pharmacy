# دليل تشغيل الإنتاج — Pharmacy

مرجع عملي لنشر وتشغيل المنصة على خادم الإنتاج. مبني على ما هو مثبت في الشيفرة الحالية
(فرع `claude/changes-not-visible-ednbw4`) لا على افتراضات.

---

## 1) متطلبات الخادم

- PHP 8.2 بامتدادات Laravel 12 المعتادة (bcmath, ctype, fileinfo, json, mbstring, openssl, pdo_mysql, tokenizer, xml, gd, zip).
- MariaDB/MySQL. **تحذير حرج:** لا تشغّل `php artisan migrate` على قاعدة فارغة — استورد
  `installation/backup/database.sql` أولًا ثم نفّذ الهجرات.
- Composer + Node (للـ build فقط؛ الأصول المبنية مضمّنة في المستودع).

## 2) جذر الاستضافة (Docroot)

النشر الفعلي لهذا المشروع يوجّه الدومين إلى **جذر المستودع** (وليس `public/`)، ولهذا كل
الأصول في القوالب عبر `dynamicAsset(path: 'public/assets/...')` تُبقي بادئة `public/`، وصور
الثيمات تُخدم من `resources/themes/...` مباشرة. إن قررت يومًا التحويل إلى docroot=`public/`
فراجع `DOMAIN_POINTED_DIRECTORY` وستحتاج نشر أصول الثيمات إلى `public/themes/` (زر «نشر
الثيم» في لوحة الأدمن يفعل ذلك)، وإلا ستظهر 404 لصور معاينة الثيمات كما يحدث على staging.

## 3) المهام المجدولة والطابور — **إلزامي**

بدونهما لا تعمل التسويات، استحقاق أرباح البائعين، التذكيرات، رسائل السلة المتروكة،
والإشعارات المُصفّاة عبر الطابور:

```cron
* * * * * cd /path/to/app && php artisan schedule:run >> /dev/null 2>&1
```

وعامل طابور دائم (عبر systemd أو supervisor):

```ini
[program:pharmacy-queue]
command=php /path/to/app/artisan queue:work --tries=3 --sleep=3
autostart=true
autorestart=true
```

شاشة «المراقبة» في لوحة الأدمن تعرض تنبيه «المجدول لا يعمل» إن غاب الكرون.

## 4) أوامر ما بعد كل نشر

```bash
php artisan optimize:clear     # مسح كل الكاش (config/route/view/cache)
php artisan view:cache         # تجميع مسبق لقوالب Blade (بوابة صياغة أيضًا)
php artisan file:permission    # إصلاح صلاحيات storage
```

## 5) ملاحظات تشغيلية لميزة دورة حياة POS (v4.0)

- طلب POS «توصيل للمنزل» يُنشأ **في انتظار** ويُدار من صفحة تفاصيل الطلب (أدمن/بائع) أو
  تطبيق المندوب — الكاش يُحصَّل عند التسليم ويتسوّى تلقائيًا (محافظ + نقد بعهدة المندوب).
- إن كان «تحقق تسليم الطلب» مفعّلًا في الإعدادات، فطلبات توصيل POS تحمل رمز تحقق مثل طلبات
  الويب — يظهر للعميل عبر إشعاراته إن كان له حساب بتوكن FCM.
- تتبع العميل لطلب POS من واجهة المتجر محجوب upstream عمدًا (رسالة «أُنشئ من نقطة البيع») —
  الإدارة كلها من اللوحات وتطبيق المندوب.

## 6) قرارات معلّقة بانتظار المالك (لا تُنفَّذ بدون إذن صريح)

1. **التحميل الكسول لحزمة Firebase (~1.4MB)** على واجهة المتجر — غير قابلة للتحقق على staging
   (لا مفاتيح Firebase)، لذا أُجّلت.
2. **حذف ملفي SQL التاريخيين** (`pharmacysyria_syriastore.sql`، `pharmacysyria_wp835.sql`)
   من تاريخ git — يحويان 13 تجزئة bcrypt و96 بريدًا؛ الحذف يتطلب **إعادة كتابة تاريخ** المستودع
   (تُغيّر كل الـ SHA وتكسر الاستنساخات القائمة) فلا تُنفَّذ إلا بقرار صريح.
3. مفاتيح `.env` المذكورة في تقرير التدقيق تُعتبر مكشوفة — **دوّرها** قبل أي إطلاق عام.

## 7) فحص سريع بعد النشر

- `/admin/orders/list/all` تعرض القائمة بعدّادات الحالات.
- بيع POS فوري يكتمل ويطبع فاتورة؛ بيع توصيل يظهر «في انتظار» في القائمة.
- تبديل اللغة للعربية: الاتجاه RTL وكل تسميات اللوحة عربية.
- `/admin/system-setup/monitoring` بلا تنبيه كرون.
